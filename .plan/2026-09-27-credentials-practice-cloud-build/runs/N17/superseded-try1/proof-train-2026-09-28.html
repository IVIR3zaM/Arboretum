Credentials kata: a fifteen-turn Train-mode calibration run, with both tickets and the feature landing at the root

A coached session run through the harness against a jailed clone of practices/credentials. All five phases ran in order. TICKET-2.md was staged in only after the gate showed Ticket 1 closed, and FEATURE-REQUEST.md only after it showed Ticket 2 closed. Every figure below is copied from a command output the harness captured. This is a calibration run, not a learner grade (AGENTS.md rule 10). The learner's prompts and the trainer's notes were written by an operator agent that could read the answer key. So the run shows how the assistant behaves and whether the traps fire. It is not evidence of how an independent learner would drive.

What this session proves

A cold assistant was driven through the kata one phase at a time: a cited research pass, two staged tickets, a feature request, an improvements pass and a review. Each ticket was reproduced as failing tests before any fix was delegated. The run ends with the gate at axis a: PASS 26/26 · axis a2: PASS 17/17 · axis b: PASS 7/7 · worst-case: PASS, and both unit suites are green.

The traps that still bite fired in phases 2–4, and each one was caught by the gate, not by the assistant's own tests. The first Ticket 2 fix passed every test the assistant wrote and still scored axis a2: FAIL 16/17. Its tests ran the notifier only under the code's own deadline, never under the runtime's. The first feature build went further than the owners' answers and scored axis b: FAIL 0/7. And an “improvements” pass changed a public type, so the Ticket 2 grader stopped compiling (axis a2: FAIL 0/0) while both suites stayed green. After a trainer note naming the discipline, each one was closed at the next checkpoint.

What did not bite. The research pass came first, as the kata intends. So the Ticket 1 plateau was never exercised and Ticket 1 converged on the first fix. The same is true of the uncoached control run. What discriminates in this kata is the Ticket 2 canary target and the feature's expiry rule, measured below, plus the driving axis.

Harness invariants applied before any prompt ran

  • ✓Cloned, stripped and jailed. The assistant worked in /tmp/cold-N17-train, a clone made outside the repo by the kit's mkclone.sh t1. _solutions/, README.md and practice.json were stripped, reference/ was present from the start, the clone had its own git init and baseline commit, and only TICKET-1.md was in it. practices/credentials/ was never touched.
  • ✓Work items staged on the gate, not on the calendar (train/staging.log): STAGED TICKET-2.md ... after checkpoints/03-ticket-1/grade.txt showed 'axis a: PASS 26/26', and STAGED FEATURE-REQUEST.md ... after checkpoints/06-ticket-2-rework/grade.txt showed 'axis a2: PASS 17/17'.
  • ✓A cold assistant, resumed turn after turn. cold-run.sh ran claude -p --model opus with no user, project or MCP settings and no web tools, then --resumed the same session for turns 2–15. meta.env records MODEL_RESOLVED=claude-opus-5-5 for every turn.
  • ✓Every turn audited. Each kept turn's audit.txt reads audit: clean. Four attempts (turns 2, 7, 12 and 14) were flagged by the jail audit. Turn 2's test wrote scratch dirs to /tmp, and turn 7 ran find /. The other two were flags the auditor raised on a // comment and a sed expression. Each flagged attempt was voided, the clone and the session store were rolled back, and the turn was re-run from the same prompt. The voided attempts are kept as turn-NN-void-1/ and are not part of the session.
  • ✓Executor ≠ examiner. Between turns an outcome checker ran practice.json's commands.install / test / grade against a throwaway copy with _solutions/ dropped in. The assistant never saw a score, only the learner's “the release check says … hasn't landed”. Axis B was graded by a separate claude -p --model opus process in a fresh session, in its own directory. It read golden/ (_solutions/ plus context/cedar goals, best practices and failure modes), the ordered transcript, the final diff and the captured outputs.

Honest limits of this run. (1) The learner was role-played by an operator agent with golden access. The prompts follow the phases the way a competent learner would. But the phase-3 owners' answers (turn 8) are feature-qa.md's content, and the phase-2 decisions attributed to Partner Success and Platform were authored, not elicited. The examiner's Source column marks these moves operator-supplied. (2) The trainer notes were written to name disciplines, never a finding, clause or number. The examiner checked each one and judged that the note after turn 5 crossed the line: it told the learner a summarised count was wrong, without giving the figure (below). (3) The Ticket 1 plateau is not measured here. The research pass preceded the fix, which is the condition under which trap-manifest.md says it cannot be measured.
