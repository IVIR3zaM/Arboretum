# N20 Cold-agent kit fix: toolchain PATH, CLI files inside the clone, heredoc-aware audit
Do: Fix three defects in the shared cold-agent kit (built by N05). They voided or falsely failed cold runs in N11 and N13. After this fix, every later cold run (the N13 re-audit, the N11 retry, N17) finds the toolchains, keeps every CLI-owned file inside the clone, and gets an audit that is no weaker and no longer falsely red. Also make the plan's verify command find the toolchains. Below, `$P` means `.plan/2026-09-27-credentials-practice-cloud-build`.
Context:
- D12: the real agent is a headless `claude -p --model opus` in a harness-shaped clone outside the repo, with web tools off and the transcript audited. Any access outside the clone voids the run. D14 applies to the audit as well: it may never get weaker. Do not widen the allowed-prefix set (`$P/scripts/cold/audit.py:46-73`), and do not allowlist anything under `$HOME/.claude` or `/tmp/claude-*`. Fix these defects by moving the CLI's files into the clone, not by excusing them.
- Defect 1, toolchain not on PATH. Cold runs and verify.sh inherit the host PATH, which lacks `$HOME/flutter-sdk/bin`. bootstrap.sh (`$P/scripts/bootstrap.sh:30-66`) only writes that entry to `.bashrc`/`.profile`, and non-interactive shells skip both. Cold agents then searched the filesystem (`ls / /opt /usr/local`, `find / -name flutter`); see `$P/runs/N13/naive-void-1/audit.txt` and `elicited-void-1/audit.txt`. verify.sh fails at `$P/scripts/verify.sh:60-62` for the same reason (`$P/log/N11.md`, C6).
- Defect 2, CLI-owned files outside the clone. The child CLI writes, and tells the agent to use, two locations outside the clone:
  - its scratchpad at `/tmp/claude-0/<sanitized clone>/<session>/scratchpad` (`$P/runs/N13/naive-void-1/audit.txt`, calls #15-17);
  - its spill file for oversized tool output at `$HOME/.claude/projects/<sanitized clone>/<session>/tool-results/` (`$P/runs/N11/void-1/audit.txt`, call #5).
  N13's replacement runs showed that `CLAUDE_CODE_TMPDIR=<clone>/.git/cc-tmp` removes the first (`$P/runs/N13/summary.md`, "Voided runs"). For the second, relocate the CLI's config dir with `CLAUDE_CONFIG_DIR=<clone>/.git/cc-config`. Both dirs sit under `.git`, so they are inside the jail and out of `diff.patch`, because `$P/scripts/cold/cold-run.sh:122-127` diffs only the work tree.
- Defect 3, false positive. audit.py expands a bare `~/` token anywhere in a Bash command, heredoc bodies included (`audit.py:91-97`, `160-174`). So Dart integer division (`ms ~/ 1000`), written through `cat > x.dart <<'EOF'` or `python3 - <<'EOF'`, reads as `$HOME` (`$P/runs/N13/naive/audit.txt`, `elicited/audit.txt`). Bash does no tilde expansion inside a heredoc body, whether the delimiter is quoted or not.
- The fix:
  - New `$P/scripts/toolpath.sh`, sourced and idempotent. It prepends `$HOME/flutter-sdk/bin` and `$HOME/.cargo/bin` to PATH when each dir exists and is not already on PATH. cold-run.sh and verify.sh both source it.
  - cold-run.sh changes:
    - Source toolpath.sh.
    - Create `$CLONE/.git/cc-tmp` and `$CLONE/.git/cc-config`, and pass `CLAUDE_CODE_TMPDIR` and `CLAUDE_CONFIG_DIR` pointing at them to the child. Both dirs persist across `--resume` turns.
    - Add `FLUTTER=$(command -v flutter)`, `CARGO=$(command -v cargo)`, `CLAUDE_CODE_TMPDIR` and `CLAUDE_CONFIG_DIR` to each meta.env block.
    - Copy nothing from `$HOME/.claude` into the clone.
    - If the relocated CLI cannot authenticate, reply BLOCKED with the CLI's error. Do not fall back to an allowlist.
  - audit.py becomes heredoc-aware. For each `<<` or `<<-` heredoc in a Bash command, whether its delimiter is quoted or not, split the body off the command line:
    - If the body feeds a shell (`bash`, `sh`, `zsh`, `dash`, `ksh`, `source`, `.`, `eval`), audit it as shell, exactly as today.
    - Otherwise treat it as data. The only change is that a `~` in it is not expanded. The absolute-path, `$HOME`/`${HOME}` and `..` checks still run on every body token.
  - Nothing else in the kit changes.
