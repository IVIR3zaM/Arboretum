- Why (D23, confirmed): N17's turn 09 was voided three times (`$P/runs/N17/train/turn-09-void-1..3/audit.txt`), each time by a false positive. There are two causes:
  - (i) A bug. `tokenize` (`audit.py:106-114`) uses shlex, and shlex treats a newline as whitespace; `SEPARATORS` (`audit.py:36`) has no newline. So in `S=<scratch>` newline `cd $S/probe/backend && … ../app`, the `cd` is not at command start, and `../app` resolves from the clone to `/tmp/app`.
  - (ii) Data bodies. `/tmp/does-not-exist-root` and `https://h.example/../../etc/passwd` in Rust test source (void-2 call #5), and a `" / "` format string (void-3 call #1). All three sit in `cat > file <<'EOF'` bodies. N20 made such bodies path-checked (`tests/run.sh:124-126`), but the same text written with the Write tool is never checked: `audit_file_tool` (`audit.py:364-379`) checks only the path keys.
- The fix (D23 (a)+(b)+(c)):
  - (a) Treat an unquoted newline in a Bash command line as a command separator, so the next word is at command start and a `cd` there moves the cwd. A newline inside quotes, and a backslash-newline continuation, are not separators. Heredoc bodies are already split off by `split_heredocs` (`audit.py:144`) and keep their own handling.
  - (b) In `audit_token` (`audit.py:347-362`), stop path-checking a part that starts with `//`, such as a URL authority left over after the `[=:]` split of `scheme://…`. This matches `looks_absolute` (`audit.py:281-288`), which already treats `//` as not a path.
  - (c) A heredoc body whose command is `cat` or `tee` and whose output goes only to a file gets audited the way Write content is: its tokens are not path-checked. Output to a file means a `>`/`>>` redirect on that simple command, or tee's file arguments, with no pipe onward. These checks stay:
    - The target path, and every other command-line token, is still checked.
    - An unquoted body's `$(...)` and backticks are still audited as shell (`audit_heredoc`, `audit.py:267-279`).
    - Any other body keeps every check. That covers bodies fed to an interpreter (`python3 -`, `node`, …) or to a shell, bodies piped onward (`cat <<EOF | …`), `cat <<EOF` to stdout, and a heredoc inside `$(…)`.
  - Move the test at `tests/run.sh:124-126` (`heredoc-data-home-dotdot`) to a `python3 - <<'EOF'` form, so it keeps its exit-1 coverage of `$HOME/.netrc` and `../../up.txt`.
