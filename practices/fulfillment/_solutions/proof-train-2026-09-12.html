The kata is complex in the fog, small in the fix. The autopilot keeps making the visible symptom go away — the web checkout passes, the ticketed SKU stops overselling — while the hidden grader that tests the availability root against the live reference/ ERP feed climbs and then plateaus red. Only leaving the repo (the research pass) reveals the rule — on-hand ≠ promisable — and the two-line root fix that makes every SKU correct at once.

Method: per the harness rules the practice is cloned and _solutions/ is stripped from the learner's view; the examiner runs bash grade.sh (which holds the hidden dual grader) after each attempt. Both runs below were executed for real; the autopilot's deliberately-wrong edits were reverted after each round (git checkout -- .), so nothing wrong was kept.

Where the autopilot is stuck
6 → 7 → 8 → 10 / 14, and never 14. The autopilot is memorizing per-SKU answers it read off the grader, not implementing a rule — and it cannot say why 22 or 5 is right, because it never left the repo to learn how ATP is computed. Backorder and exactly-zero SKUs remain, and the next reservation change would break the "fixed" ones. This is delegation-before-comprehension: every round looks like progress; none converges.

The winning path — a disciplined run that converges

1 Understand + the research pass (beats FM-16 / FM-15)

Driver
"Before any edit: this talks to a hosted ERP. Read everything under reference/ and write me a research-notes.md of the load-bearing facts. Treat the READMEs as stale until verified."
What it learned (from reference/, not the repo)

Availability is a live query keyed on (SKU, location) returning ATP, where ATP = on_hand − reserved − allocated + inbound-within-lead-time, and on-hand is not promisable. The reserved/allocated/inbound numbers live only in the hosted feed; the local snapshot is a stale copy. The backend README (stock_count), a code comment ("nightly snapshot"), and the "a DB constraint prevents oversell" line are all stale/false. establish-cross-boundary-context ✓ · reconcile-docs ✓

2 Reproduce before fixing (beats FM-01 / FM-02)

Driver
"Pin the prod oversell with a failing test against the live feed first — SKU-1002's true ATP is 22, so confirming an order for 30 must be refused."
Real outcome — the bug, reproduced
# added backend/test/reproduce.test.ts, ATP_SOURCE=live
# tests 27 / # pass 26 / # fail 1   ← the reproduction fails: the root oversells

reproduce-before-fix ✓

3 Fix the ROOT, not the symptom (beats FM-13)

The two-line fix — the resolver computes ATP
// backend/src/availability.ts — the live branch
- return rec.on_hand;               // the abandoned "availability = on-hand" assumption
+ return computeAtp(rec);           // + import { computeAtp } from "./atp.ts";

computeAtp already existed in atp.ts, unit-tested; the stale path simply never called it.

Real outcome — converges for every SKU at once
