How it was run (harness)

The five phases

1 Understand — map both packages + the research pass

Learner prompt
“Before any edits: map the backend and web packages and the invariant each owns. This talks to a hosted ERP — read everything under reference/ and write me a research-notes.md of the load-bearing facts. Don't change anything yet.”
Assistant behaviour

Distilled reference/erp-availability-contract.md + atp-spec.md: availability is a live query keyed on (SKU, location) returning ATP, where ATP = on_hand − reserved − allocated + inbound-within-lead-time — and on-hand is not promisable. Noted the docs are stale (README says stock_count, web says GET /stock, a README line claims a DB constraint prevents oversell).

Trap by design (FM-16 / FM-15)

The reserved/allocated/inbound truth lives only in reference/; a single-scope run that never opens it assumes the local snapshot is authoritative. The prose actively misleads. The research pass is the escape.

Outcome

research-notes.md written; learner enters the fix with a model of the system, not the README. discipline: establish-cross-boundary-context ✓ · reconcile-docs ✓

2 Fix the bug — reproduce, then fix the root

Learner prompt
“TICKET.md says we oversell in prod on a few pre-sold SKUs but it's green on staging. Reproduce it with a failing test against the real feed first, then fix the root. bash grade.sh is the gate.”
Assistant behaviour

Added a reproduction test pointing the resolver at the live feed and asserting SKU-1002 (true ATP 22) refuses an order for 30. Traced the answer to availability.ts availableToPromise, whose live branch returns rec.on_hand (with a misleading "mirrors the nightly snapshot" comment) instead of computeAtp(rec) — which already exists in atp.ts and is unit-tested.

cd backend && npm test   →  # tests 27 / # pass 26 / # fail 1   (reproduction fails: oversell confirmed)
Traps by design (FM-13) — both shallow fixes stay red

A symptom-patch at the checkout call site and a hard-code of the one ticketed SKU were both offered by autopilot. Measured, both leave the root-tested grader red (see the trap table below). Only computing ATP at the resolver root generalizes.

The fix (two lines)
// backend/src/availability.ts — live branch
- // Live ERP availability; mirrors the nightly availability_snapshot's on-hand figure.
- return rec.on_hand;
+ // Live ERP availability: promisable = ATP, not raw on-hand (see reference/atp-spec.md).
+ return computeAtp(rec);          // + import { computeAtp } from "./atp.ts";
Real outcome
cd backend && npm test   →  # tests 27 / # pass 27 / # fail 0
bash grade.sh            →  backend 14/14 · web 2/2 · RESULT: PASS (exit 0)

reproduce-before-fix ✓ · model-before-delegation ✓ · fixed the root, not the symptom ✓

3 Feature — the 10-minute cart hold (minimal correct)

Learner prompt
“FEATURE-REQUEST.md wants a 10-minute cart hold. Before you build it, what do you need to know?”
Assistant behaviour + requirements elicited

Surfaced the held-back questions before coding: does a hold decrement ATP for others (yes — reserve against live ATP); keyed on cart or (SKU, cart) (the business entity); TTL release (swept, never leaked); re-checked at confirm (yes). Then built exactly that and deferred the rest out loud (no un-hold-beyond-release, no per-cart limits, no billing).

Trap by design (FM-03 / FM-07 / read-before-delegate)

A naive hold double-counts, holds against the stale snapshot, or leaks forever. Reading how confirm decides availability first — and reserving against the now-correct live ATP — avoids all three. Rewriting the placeholder store meant its obsolete test was replaced, not left to rot.

Real outcome
cd backend && npm test   →  # tests 28 / # pass 28 / # fail 0   (repro + 5 hold tests; obsolete placeholder test removed)
cd ../web  && npm test   →  Tests  10 passed (10)
bash grade.sh            →  backend 14/14 · web 2/2 · RESULT: PASS (exit 0)

requirements-elicitation ✓ · restraint / altitude-match ✓ · read-before-delegate ✓

4 Improve — surface the latent defects, don't sprawl

Learner prompt
“Find — don't recite — the highest-value correctness/robustness issues still in the code, ranked, with evidence. Fix only what's in scope; surface the rest.”
Assistant behaviour

Surfaced, from the code: idempotency keyed on the transport requestId not the business key (FM-06); the reservation store returning internals by reference (FM-05); the strict qty/zero-ATP boundary (FM-04); the inbound window using < where the spec says ≤ (FM-03); an unbounded holds map absent the TTL sweep the feature added (FM-07); an unvalidated location code (FM-08). Named each with a fix; did not balloon the diff.

Outcome

latent defects found, not recited ✓ · restraint ✓

5 Review — intent & triage

Learner prompt
“Review the diff as a teammate's PR: what did you verify, what's a weakness in your own change, and what would make you revisit it?”
Outcome (FM-14)

Anchored the review on the ticket's intent (no oversell against live ATP), separated the load-bearing two-line fix from the feature, and named a real trade-off: the hold store is in-memory and single-process — fine for the kata, revisit if holds must survive a restart or span instances. review with intent + triage ✓
