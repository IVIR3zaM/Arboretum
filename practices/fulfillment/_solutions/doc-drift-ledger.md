# doc-drift-ledger — every planted contradiction, and why

> Spoiler / answer key. Examiner-only; stripped from the learner clone. Each row: what a
> learner/assistant would encounter locally, its authoritative source, and why the local doc is
> wrong. This is the reconcile-docs (FM-15) answer key.

| Where the drift lives | What it claims | Authoritative source | Why it's wrong / what to trust instead |
|---|---|---|---|
| `backend/README.md`: "Stock is decremented from `stock_count` on each order, so on-hand always reflects outstanding orders without a separate reconciliation step." | Describes the **first** era of the repo's history — a mutable local counter directly decremented per order. | Current code (`backend/src/availability.ts`, `erpFeed.ts`, `atp.ts`) + `reference/erp-availability-contract.md`. | Stale by **two migrations**: `stock_count` → nightly `availability_snapshot` → live ATP. There is no `stock_count` anywhere in the current source; availability is either a live ATP query or a read-only snapshot fixture, never a counter decremented in place. A prompt that trusts this line would look for a decrement-on-order code path that doesn't exist and could "fix" the wrong thing entirely. |
| `backend/src/availability.ts`: the `live`-branch comment — "Live ERP availability; mirrors the nightly availability_snapshot's on-hand figure." | Frames the live branch's `on_hand` return as an intentional mirror of the (already-superseded) nightly snapshot. | `reference/atp-spec.md` (on-hand ≠ promisable; the formula) — which lives **only** in `reference/`, not in any local file. | Accurately describes what the code *does*, but not what it *should* do at the live-ATP stage of the migration — FM-15's "stale code path with no doc trace" in its purest form: the comment is internally consistent with the buggy code, which is why re-reading it doesn't catch the bug. Note there is **no** correct ATP function locally to fall back on — the only local helper, `atp.ts`'s `promisableStock` (`on_hand − reserved`), is itself stale and incomplete (misses `allocated` and inbound-within-lead-time). The authoritative rule exists only in `atp-spec.md`. |
| `web/README.md`: "Stock levels are read via `GET /stock`, keyed by SKU and location, and returned as `{ sku, location, atp, inStock }`." | Names the endpoint `GET /stock`. | `backend/README.md`'s own Endpoints section (`GET /availability`) + `backend/src/availability.ts`'s `checkAvailability`, which the storefront's `web/src/client.ts` calls (in-process, via `StoreClient`). | The route was renamed at some point from `/stock` to `/availability` (consistent with the `stock_count` → ATP migration's vocabulary shift) and the storefront README was never updated. The response *shape* described (`{sku, location, atp, inStock}`) does match the current `Availability` type in `types.ts` — only the endpoint name drifted, which makes the line easy to half-trust and miss the one wrong word. |
| Field-name drift across the codebase: `stock_count` (README-only, no longer in code) / `on_hand` (current field on `FeedRecord`, snapshot's internal name) / `atp` (the only field ever returned across a service boundary — `Availability.atp`, the ERP contract's `atp`). | Three names in circulation for inventory-adjacent numbers, from three eras. | `reference/atp-spec.md`'s Inputs table + `types.ts`'s `Availability`/`FeedRecord` interfaces. | **`atp` is the only name safe to treat as "what we can promise."** `on_hand` is a real, current field — but it is one *input* to the ATP formula, never itself promisable, and code or docs that use `on_hand` and `atp`/availability interchangeably are repeating the primary bug's own confusion at the naming level. `stock_count` no longer exists in code at all; encountering it only in prose is itself a tell that the doc predates the current design. |

Flag it as a contradiction to reconcile rather than a fact to build on; do not let a feature-implementation prompt cite this line as a reason a safety check is unnecessary. The top-level learner README (N7's job, not this file's) is the one that will actually carry this line into the clone. |

## How to use this table

A learner's `research-notes.md` doesn't need to reproduce this exact table, but a research pass
that never notices *any* of these — especially the `stock_count` line or the `GET /stock` name —
and instead builds toward what the stale doc describes is a clear FM-15 miss (see `rubric.md`).
The tell in a transcript is a prompt or summary that repeats one of the left-hand-column claims
as current fact rather than flagging it against the right-hand-column source.
