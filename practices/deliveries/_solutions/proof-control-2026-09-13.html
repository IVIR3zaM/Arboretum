Deliveries kata — what an uncoached assistant actually scores

Every trap in this kata was verified by hand and every mechanism holds. Then the kata was handed to a fresh assistant with one casual prompt and no coaching, twice. This page records what happened, including the part that is not flattering.

The finding, up front

A fresh assistant was given a harness-shaped clone and one sentence — “here's a ticket and a feature request, fix the bug and implement the feature” — with no follow-up and no coaching. It scored 13/13 on the hidden grader. The run was repeated after every coaching line was stripped out of the practice, and it scored 13/13 again. So this page proves two things at once: the material was giving the answer away and no longer does, and cutting that out did not make the objective gate hard. For an assistant of this class the gate is a floor, not a discriminator — what separates a good run from a bad one is the transcript, and the last section says exactly which parts of it.

Both arms were run as jailed sub-agents that could read and write nothing outside their own clone, were told the engineer was unavailable for questions (so the run stayed a genuine one-shot), and were graded afterwards by copying _solutions/ into a throwaway copy — the arms never saw the grader. No phases. No “reproduce first”. No mention of a grader. This is the casual drop-in the kata claims to punish.

What both arms did

Found the root in cutoffInstant — Subscription.timezone declared, documented, and read by no code at all. Replaced the host-local new Date(y, m, d, h) with a per-instant Intl.DateTimeFormat conversion. Wrote timezone regression tests that assert absolute instants. Handled the DST gap and the fall-back fold deliberately. Then read repository.ts, found the lazy materialization and the duplicate invariant on their own, and implemented skip as materialize-then-skip, idempotent, refusing a box that had already shipped.

Traps that did not fire
The fixed-offset plateau (arm B reached for Intl immediately, never the shortcut). The duplicate-delivery trap (both arms read the store before writing the feature — arm B without any hint that there was something to read). The green-suite trap (both distrusted the suite unprompted). Every autopilot trap in the manifest assumes an autopilot that no longer exists at this model class.

What run A exposed — the material was doing the learner's job

Run A is why this page exists. Before grading anything, the clone was read the way the assistant reads it, and the exercise was found to be narrating its own answer. Each of these is now fixed; the fix is the right-hand column.

The rule that came out of this is now Context alder@1.2.0 invariant 10 — nothing the assistant can read coaches it — plus the harness rule that the clone carries the service repo and the work items only. A trap the workdir warns about measures nothing.

The grader grew from 8 cases to 13 in this same change: practice.json claimed a feature trap that no test enforced, so five cases now cover the minimal agreed behaviour from feature-qa.md through the public surface only. Two independently written correct implementations (the two control arms) both score 13/13, so the new cases are not overfitted to one solution.

So what does still discriminate?

Exactly the things a one-shot cannot do. All of them live on the driving axis, and all of them are visible in what the control runs handed back:

  • 1
    It could not ask. Idempotency and the shipped-box refusal are not deducible from the repo. Run B guessed both, then wrote: “this is the ambiguity I'd most want confirmed — the alternative reading is ‘skip one more box’, and a double-click on the UI makes these differ.” That is the question the learner was supposed to put to the PM before the code existed. It guessed right and said so; a learner who asks does not have to be lucky.
  • 2
    It did not hold scope. Asked for a cutoff fix and a skip method, both arms also rewrote the “today” computation in scheduling.ts and service.ts; one rewrote demo.ts. Plausible changes. Nobody asked for them. That is FM-10 in its natural habitat, and it is the headline failure this kata grades.
  • 3
    Nobody reviewed it. Both arms returned a confident summary of their own work. Phase 5 exists because that summary is the cheapest artifact in the transcript and the easiest thing in the world to rubber-stamp.
  • 4
    It shipped guesses as decisions. Run B's own list of assumptions is five items long. Each one is a place where a customer-visible rule was chosen by an assistant and ratified by nobody.

How to grade after this. A 13/13 with no questions asked, three unrequested modules touched and a rubber-stamp review is a worse run than a 12/13 that asked about the two unstated rules, stayed inside the ask, and named its own weakness. The oracle says the work compiles. The transcript says whether anyone was driving.
